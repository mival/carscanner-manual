ÚvodIntroduction

Návod popisuje aplikaci Car Scanner Pro (Android, verze 2.2.42, databáze profilů 2.2.42) s adaptérem Vgate vLinker (Bluetooth). Screenshoty jsou z Škody Octavia 3 (2018, 2.0 TSI DKZA, DSG DQ381) s profilem Skoda MQB: TSI/TFSI EA888 Gen.3B, EA888 Evo4 (Gen.4) 2.0L (with Miller cycle).

Osobní údaje (VIN, MAC adresa adaptéru, kontakty, stavový řádek) jsou ve screenshotech rozmazané. Na obrázek klepněte pro zvětšení; řady screenshotů se posouvají do strany.

Tato verze pokrývá obrazovky dostupné bez připojení k autu. Palubní deska s hodnotami, živá data, chybové kódy a řídicí jednotky budou doplněny.

This guide covers the Car Scanner Pro app (Android, version 2.2.42, profile database 2.2.42) with a Vgate vLinker Bluetooth adapter. Screenshots come from a Škoda Octavia 3 (2018, 2.0 TSI DKZA, DSG DQ381) using the Skoda MQB: TSI/TFSI EA888 Gen.3B, EA888 Evo4 (Gen.4) 2.0L (with Miller cycle) connection profile.

Personal data (VIN, adapter MAC address, contacts, status bar) is blurred. Tap a screenshot to enlarge it; screenshot rows scroll sideways.

This version covers the screens available without a car connection. Dashboard values, live data, trouble codes and control units will be added later.

Log komunikace (Exportovat protokol)Communication log (Export log)

Nastavení → Adaptér OBDII ELM327 → (dole) Exportovat protokol otevře systémové sdílení se souborem log.txt. Uložte ho např. přes Moje soubory → Uložit do (složka Download).

  • Log se zapisuje automaticky, nic se nezapíná. Je kumulativní (obsahuje i starší relace), řazený po relacích s hlavičkou ===== LOG STARTED: datum =====.
  • Obsahuje každý příkaz a odpověď: ATSH7E0 (hlavička), 2214CB (dotaz), 7E8 04 62 14 CB 05 (odpověď). Z toho lze odvodit vlastní PID pro jiné aplikace (Torque Pro).
  • Záznamy jízd (Záznam dat) obsahují jen hodnoty, ne surovou komunikaci.
Log obsahuje VIN a případně i servisní operace (mazání chyb, kódování). Nesdílejte ho veřejně.
Příklad využití: kvalt z řídicí jednotky motoru je v logu dotaz 2214CB na hlavičku 7E0; v Torque Pro rovnice SIGNED(A) (R = −1, P/N = 0, 1–7).

Settings → Adapter OBDII ELM327 → (bottom) Export log opens the system share sheet with log.txt. Save it e.g. via My Files → Save to (Download folder).

  • Logging is always on; nothing needs enabling. The log is cumulative (older sessions included), split into sessions with a ===== LOG STARTED: date ===== header.
  • It contains every command and response: ATSH7E0 (header), 2214CB (request), 7E8 04 62 14 CB 05 (response). You can derive custom PIDs for other apps (Torque Pro) from it.
  • Trip recordings (Data recording) contain values only, not raw communication.
The log contains the VIN and possibly service operations (DTC clearing, coding). Don't share it publicly.
Example: the engine ECU gear is request 2214CB on header 7E0; in Torque Pro use equation SIGNED(A) (R = −1, P/N = 0, 1–7).

Rámec ISO-TP

První bajt dat (PCI) říká typ rámce: 0x jednorámcová zpráva (x = délka), 1x xx první rámec dlouhé zprávy (12bitová délka), 2x pokračovací rámec (x = pořadí), 30 řízení toku. Nevyužité bajty se vyplňují (u VAG AA).

Příklad 1 – OBD-II režim 01 (více PID najednou)

>01050C0D4
7E8 10 08 41 05 3F 0C 00 00
7E8 21 0D 00 AA AA AA AA AA
7E9 10 08 41 05 3F 0C 00 00
7E9 21 0D 00 AA AA AA AA AA

Dotaz na funkční adresu 7DF: PID 05 (teplota kapaliny), 0C (otáčky), 0D (rychlost). Odpověď je dlouhá 8 bajtů (10 08), takže přijde ve dvou rámcích; odpověděly obě jednotky. 41 = kladná odpověď na režim 01 (služba + 0x40). Hodnoty: 3F → 63 − 40 = 23 °C, 00 00 → 0 ot/min, 00 → 0 km/h.

Příklad 2 – UDS služba 22 (kvalt)

ATSH7E0
>2214CB1
7E8 04 62 14 CB 05
7E8CAN ID 04PCI: 4 B 6222+40 14DID CBDID 05A

Služba 22 (ReadDataByIdentifier) čte údaj s identifikátorem (DID) 14CB. Kladná odpověď 62 zopakuje DID a pak následují data. Bajt 05 = 5. rychlostní stupeň (FF = −1 = zpátečka, 00 = P/N).

Příklad 3 – dlouhá odpověď a „čekej“

>22F19E
7E8 03 7F 22 78
7E8 10 1C 62 F1 9E 45 56 5F
7E8 21 45 43 4D 32 30 54 46
…

7F 22 78 = záporná odpověď s kódem 78 – response pending (jednotka ještě pracuje). Pak přijde první rámec (10 1C = 28 bajtů) a pokračovací rámce 21, 22… Data jsou ASCII text (45 56 5F 45 43 4D… = „EV_ECM…“, identifikace datového souboru jednotky).

Od logu k vlastnímu PID (Torque Pro)

  1. V Car Scanneru zobrazte jen hledaný senzor a měňte jeho hodnotu (řazení, zahřátí…).
  2. Exportujte log a najděte poslední ATSH… před dotazy 22xxxx.
  3. Najděte DID, jehož data se mění souběžně se zobrazenou hodnotou.
  4. V Torque: ModeAndPID = 2214CB, Header = 7E0, Equation s proměnnými A, B… = datové bajty za 62 14 CB (např. SIGNED(A), (A*256+B)/10, A-40).
  5. Ověřte v autě proti Car Scanneru.

This chapter explains what happens between the phone and the car so you can read the communication log and derive custom PIDs from it. Examples are real lines from this Octavia's log (spaces added for readability).

Layers

App – Car Scanner / Torque: sends text commands, computes values from formulas.
ELM327 adapter (vLinker) – turns text (Bluetooth serial link) into CAN frames; controlled by AT commands.
Diagnostic services – OBD-II (modes 01, 09…, emission data, every car) and UDS (ISO 14229, services 22, 19…, manufacturer data).
ISO-TP transport (ISO 15765-2) – splits longer messages into 8-byte frames.
CAN – the bus on the OBD connector (pins 6 and 14), 500 kbit/s, 11-bit identifiers (ISO 15765-4).

Addresses (CAN IDs)

Request IDResponse IDWho
7DFall 7E8–7EFfunctional (broadcast) request – every emission ECU answers
7E07E8engine control unit (ECM, Simos 18)
7E17E9transmission control unit (TCM, DSG DQ381)
e.g. 710, 714other (e.g. 77A, 77E)other VAG units behind the gateway (gateway, cluster…) – IDs vary by car

A physical response is usually request ID + 8. On VAG cars diagnostics pass through the gateway (J533), which only forwards diagnostic traffic to the OBD connector.

ELM327 adapter commands

CommandMeaning
ATZ, ATE0reset adapter, echo off
ATSP6 / ATSP0protocol ISO 15765-4 CAN 11-bit 500 kbit/s / automatic
ATH1show CAN IDs in responses (that's why the log contains 7E8…)
ATSH7E0set the ID that following requests go to (header)
ATCRA77A / ATARreceive only the given response ID / automatic filter
ATFCSH7E1ID for flow-control frames during long responses
ATST64response timeout (×4 ms)

A trailing digit on a request (e.g. 2214CB1) tells the adapter how many responses to expect – it speeds up reading.

ISO-TP frame

The first data byte (PCI) gives the frame type: 0x single frame (x = length), 1x xx first frame of a long message (12-bit length), 2x consecutive frame (x = sequence), 30 flow control. Unused bytes are padded (AA on VAG).

Example 1 – OBD-II mode 01 (several PIDs at once)

>01050C0D4
7E8 10 08 41 05 3F 0C 00 00
7E8 21 0D 00 AA AA AA AA AA
7E9 10 08 41 05 3F 0C 00 00
7E9 21 0D 00 AA AA AA AA AA

Functional request to 7DF: PID 05 (coolant temperature), 0C (RPM), 0D (speed). The answer is 8 bytes long (10 08), so it arrives in two frames; both units answered. 41 = positive response to mode 01 (service + 0x40). Values: 3F → 63 − 40 = 23 °C, 00 00 → 0 rpm, 00 → 0 km/h.

Example 2 – UDS service 22 (gear)

ATSH7E0
>2214CB1
7E8 04 62 14 CB 05
7E8CAN ID 04PCI: 4 B 6222+40 14DID CBDID 05A

Service 22 (ReadDataByIdentifier) reads data identifier (DID) 14CB. The positive response 62 echoes the DID followed by the data. Byte 05 = 5th gear (FF = −1 = reverse, 00 = P/N).

Example 3 – long response and “wait”

>22F19E
7E8 03 7F 22 78
7E8 10 1C 62 F1 9E 45 56 5F
7E8 21 45 43 4D 32 30 54 46
…

7F 22 78 = negative response with code 78 – response pending (the unit is still working). Then the first frame arrives (10 1C = 28 bytes) followed by consecutive frames 21, 22… The data is ASCII text (45 56 5F 45 43 4D… = “EV_ECM…”, the unit's data file identifier).

From the log to a custom PID (Torque Pro)

  1. In Car Scanner show only the wanted sensor and make its value change (shifting, warming up…).
  2. Export the log and find the last ATSH… before the 22xxxx requests.
  3. Find the DID whose data changes together with the displayed value.
  4. In Torque: ModeAndPID = 2214CB, Header = 7E0, Equation using A, B… = data bytes after 62 14 CB (e.g. SIGNED(A), (A*256+B)/10, A-40).
  5. Verify in the car against Car Scanner.

Supported sensors test

At the end of the profile lists there are Set all to “enabled” and Run supported sensors test (needs a connection, ideally with the engine running). The test disables sensors the car doesn't answer – on this Octavia 3 DKZA 411 of 528 stayed active and 117 were disabled. Fewer enabled sensors = faster refresh.

Tap a sensor to open its detail: custom name, priority, role and units. The app does not show the request or formula of profile sensors – you only get those from the communication log.

Enabling/disabling sensors is not stored in the app backup.

BezpečnostSafety

  • Čtení dat (OBD režim 01, UDS dotaz 22) je bezpečné.
  • Kódování, adaptace, servisní funkce, mazání chyb a zápis (UDS 2E, 31, 11, 14) mění řídicí jednotky. Před kódováním si uložte zálohu kódování a identifikace jednotek.
  • Za jízdy aplikaci neovládejte; pro Android Auto nastavte palubní desku předem.
  • Reading data (OBD mode 01, UDS service 22) is safe.
  • Coding, adaptations, service functions, clearing codes and writes (UDS 2E, 31, 11, 14) change the control units. Back up coding and unit identification before coding anything.
  • Don't operate the app while driving; set up the Android Auto dashboard beforehand.

Diagnostic trouble codes (DTC)

The intro page explains code types (stored, pending, permanent) and how to clear. Read → mode Automatic (recommended) or Advanced, option to show archived codes → list: code, control unit, status and description; tap to search the description online. Buttons Export and Clear.

  • Testy zrychlení: měření časů 0–100 km/h apod.

Freeze frame, monitors, ECU identifiers, tests

  • Freeze frame: sensor values stored when a fault occurred (if the ECU provides them).
  • Noncontinuous Monitors: OBD test results (value, minimum, maximum, PASSED/FAILED).
  • ECU identifiers: choose control units from the profile list (VAG: gateway, transmission, ABS, engine…) and read their identification and coding – handy as a backup.
  • Acceleration tests: 0–100 km/h timings etc.
  • Emission tests: readiness of emission monitors since DTC clear and for the current cycle (pre-inspection check).

Torque Pro a Android Auto – vlastní PID pro OctaviiTorque Pro and Android Auto – custom PIDs for the Octavia

Car Scanner zobrazuje v Android Auto jen text a data neumí předat jiné aplikaci. Pro grafické budíky v Android Auto se proto používá Torque Pro s pluginem AA Torque. Torque ale výrobcové senzory nezná – je potřeba mu zadat vlastní PID (dotaz, hlavičku a rovnici). Ty se zjistí z logu komunikace Car Scanneru.

Hodnoty níže platí pro Octavii 3 (5E) 2018, 2.0 TSI DKZA (Simos 18), DSG DQ381. U jiného motoru nebo převodovky se DID mohou lišit. Všechny dotazy jsou jen čtecí (služba 22).

Postup

  1. Zjištění DID: v Car Scanneru dejte na stránku palubní desky jen hledané senzory, projeďte se a exportujte log. V logu najdete ATSH… (hlavička) a dotazy 22xxxx s odpověďmi 62 xx xx …. Pořadí dotazů odpovídá pořadí položek na palubní desce.
  2. Rovnice: spárujte surové bajty s hodnotou, kterou Car Scanner zobrazil. Nejpřesnější je záznam jízdy (.brc): obsahuje zobrazené hodnoty, takže stačí porovnat se surovou odpovědí ze stejné jízdy (např. posilovač brzd: 0x5A6A = 23 146 a Car Scanner ukázal 925,84 hPa → /25).
  3. Import do Torque: CSV se sloupci Name, ShortName, ModeAndPID, Equation, Min, Max, Units, Header (+ startDiagnostic, stopDiagnostic, scale, minimumRefreshDelayMillis) uložte do Android/data/org.prowl.torque/files/extendedpids/ nebo do Download a v Torque dejte Nastavení → Správa dalších PID/Sensors → ⋮ → Import CSV file. CSV neotevírejte v Excelu (z hlavičky 7E0 udělá číslo).
  4. Ověření: porovnejte hodnotu v Torque s Car Scannerem; nefunkční PID (stále 0, „-“, nesmysl) smažte.
  5. AA Torque: v aplikaci AA Torque nastavte dashboardy (3 budíky + 4 hodnoty na stránku) a ikonou oka zkontrolujte náhled.

Kdy brzdí ACC a svítí brzdová světla

Spínač brzdových světel u pedálu při brzdění adaptivním tempomatem nesepne a brzdný tlak od pedálu je 0. Brzdění ACC se pozná ze zrychlení vozu: pedál plynu 0 %, spínač 0 a zrychlení pod −0,7 m/s². Podle předpisu UN R13-H musí automatické brzdění nad touto hranicí rozsvítit brzdová světla; v jízdách této Octavie ACC brzdilo typicky −1 až −1,7 m/s².

Tipy a úskalí

  • Úprava PID v Torque zruší jeho přiřazení v AA Torque – budík zůstane prázdný, je potřeba ho vybrat znovu.
  • Smazání PID neodebere položku ze seznamu logování (Záznam a odesílání dat → Vyberte pro záznam) – odeberte ji tam ručně, jinak Torque čte neexistující PID.
  • Torque neumí vícenásobný dotaz (např. 010C0D) ani podmínky v rovnici.
  • Trip log Torque zapisuje teploty ve °F a tlaky přepočtené na psi (÷ 14,5).
  • Čím víc PID je v logu a na budících, tím pomaleji se obnovují (≈ 0,1 s na dotaz).
  • Adaptér zvládne jen jedno spojení – Car Scanner a Torque nepouštějte současně.

In Android Auto Car Scanner shows text only and cannot pass data to other apps. Graphical gauges in Android Auto therefore use Torque Pro with the AA Torque plugin. Torque does not know manufacturer sensors – you add custom PIDs (request, header, equation), found in Car Scanner's communication log.

The values below apply to an Octavia 3 (5E) 2018, 2.0 TSI DKZA (Simos 18), DSG DQ381. Other engines or gearboxes may use different DIDs. All requests are read-only (service 22).

Procedure

  1. Find DIDs: put only the wanted sensors on a Car Scanner dashboard page, drive and export the log. Look for ATSH… (header) and 22xxxx requests with 62 xx xx … responses. The polling order matches the dashboard item order.
  2. Equation: match raw bytes with the value Car Scanner displayed. Most precise is the trip recording (.brc), which stores displayed values – compare with the raw response from the same drive (e.g. brake booster: 0x5A6A = 23 146 shown as 925.84 hPa → /25).
  3. Import into Torque: a CSV with Name, ShortName, ModeAndPID, Equation, Min, Max, Units, Header (+ startDiagnostic, stopDiagnostic, scale, minimumRefreshDelayMillis) goes into Android/data/org.prowl.torque/files/extendedpids/ or Download; in Torque use Settings → Manage extra PIDs/Sensors → ⋮ → Import CSV file. Don't open the CSV in Excel (it turns header 7E0 into a number).
  4. Verify: compare Torque with Car Scanner; delete PIDs that stay 0, “-” or nonsense.
  5. AA Torque: set up dashboards in the AA Torque app (3 gauges + 4 values per page) and check them with the eye icon.

When ACC brakes and the brake lights come on

The brake light switch at the pedal does not close during adaptive cruise control braking and pedal brake pressure stays 0. ACC braking shows up in vehicle acceleration: accelerator 0 %, switch 0 and acceleration below −0.7 m/s². Under UN R13-H automatic braking above this threshold must light the brake lights; on this Octavia ACC braked typically at −1 to −1.7 m/s².

Tips and pitfalls

  • Editing a PID in Torque removes its assignment in AA Torque – the gauge goes blank and must be picked again.
  • Deleting a PID does not remove it from the logging list (Data logging & upload → Select what to log) – remove it there too, otherwise Torque keeps querying a missing PID.
  • Torque can't do multi-PID requests (e.g. 010C0D) or conditions in equations.
  • Torque trip logs store temperatures in °F and pressures converted to psi (÷ 14.5).
  • The more PIDs logged and shown, the slower the refresh (≈ 0.1 s per request).
  • The adapter handles one connection – don't run Car Scanner and Torque at the same time.
